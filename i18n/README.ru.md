## ⛵ Что такое Vela?

Vela — это **локальный шлюз маршрутизации AI + панель управления**. Вы направляете каждый AI-инструмент на одну конечную точку — `http://localhost:32060/v1` — и Vela решает, какой провайдер ответит на самом деле: сначала ваши платные подписки, затем дешёвые API-маршруты, последними — бесплатные тарифы. Когда один маршрут иссякает, ветер подхватывает следующий. Никаких изменений на стороне инструментов, никакого простоя.

```
┌──────────────┐
│  Your tools  │  Claude Code · Codex · Cursor · Cline · OpenCode · …
└──────┬───────┘
       │  http://localhost:32060/v1   (OpenAI-compatible)
       ▼
┌─────────────────────────────────────────────────────┐
│                  Vela — the gateway                 │
│  RTK token saver · format translation · quota track │
│  combo fallback · multi-account · OAuth refresh     │
└──────────┬──────────────────────────────────────────┘
       ├─→ Tier 1  SUBSCRIPTION   Claude, Codex, Copilot, Cursor…
       ├─→ Tier 2  PAY-PER-USE    GLM, MiniMax, DeepSeek, Qwen…
       └─→ Tier 3  FREE           Kiro, OpenCode Free, MiMo Free…
       Result: every subscription token spent, every rate limit routed around.
```

Один процесс Node обслуживает оба движка: **панель управления + API** (`src/`, приложение Next.js App Router) и **движок маршрутизации** (`open-sse/`), на порту **32060**. Состояние по умолчанию живёт в SQLite и может обзавестись близнецом MariaDB, когда вы того захотите (`sqlite` → `mysql` → `mirror`). Запечатанный движок резервного копирования следит за грунтом гавани, а шлюз ставит печать на каждый релиз, чтобы корпус всегда можно было доказать.

> 📌 **Примечание:** Vela идёт собственным курсом — AI-шлюз, выкованный в открытых водах, со всеми собственными системами: хранение, резервное копирование, ценообразование и категории. CLI устанавливается как `vela` из npm. Линия форка: начиная с v0.6.0 шлюз распространяется под лицензией MIT и полностью автономен (см. [Происхождение](#-происхождение-и-лицензия)).

> 🔢 **Дисциплина счёта** (измерено 2026-10-28, на v1.2.5). Реестр провайдеров сообщает **три честных числа, и они различаются**: **189** файлов реестра на диске → **186** импортированы сгенерированным индексом → **145** подключаемых чат-транспортов (остальные 41 импортированных маршрута несут транспорты медиа, поиска и эмбеддингов, которые законно не говорят на языке чата). Три файла лежат на диске намеренно скрытыми от индекса (`trae`, `devin-cli`, `windsurf`). Никогда не сливайте эти три числа в одно — называйте, какое именно имеете в виду, и пересчитывайте, а не доверяйте этой строке:
> ```bash
> ls open-sse/providers/registry/*.js | grep -v index.js | wc -l      # 189 files on disk
> node -e "import('./open-sse/providers/registry/index.js').then(m=>console.log(m.default.length))"   # 186 imported
> node -e "import('./open-sse/providers/index.js').then(m=>console.log(Object.keys(m.PROVIDERS).length))"  # 145 dialable
> ```
> Перепись закреплена как свойство тестом `tests/unit/provider-registry-census.test.js` — файл, появившийся на диске без импорта, краснеет там раньше, чем тихо погаснет. См. [docs/PROVIDERS.md](../docs/PROVIDERS.md).

## 🤔 Зачем Vela?

| Проблема | Что делает Vela |
|-|-|
| ❌ Квота подписки истекает неиспользованной | ✅ Отслеживание квот + автоматическое резервирование — израсходуйте каждый токен до сброса |
| ❌ Лимиты запросов останавливают вас посреди работы | ✅ Ротация нескольких аккаунтов + резервирование по комбинациям моделей, нулевой простой |
| ❌ Выводы инструментов сжигают токены (диффы, grep, ls…) | ✅ **RTK-экономитель токенов** сжимает содержимое `tool_result` на месте — экономия 20–40% |
| ❌ Оплата $20–50 в месяц за каждого провайдера | ✅ Один шлюз поверх подписочных + дешёвых + бесплатных маршрутов |
| ❌ Каждому инструменту нужна своя конфигурация | ✅ Одна конечная точка, совместимая с OpenAI — её понимает любой инструмент |
| ❌ Провайдер падает — и ваш поток падает вместе с ним | ✅ Предохранитель + пороги отказов провайдера + окна остывания |

## ✨ Ключевые возможности

**🧭 Маршрутизация и трансляция**
- Одна конечная точка, совместимая с OpenAI: `/v1/chat/completions`, `/v1/messages` (нативный Claude), `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech` · `/v1/audio/transcriptions` · `/v1/audio/voices`, `/v1/videos/*` (генерация, правки, расширения), `/v1/responses` (+`/compact`), `/v1beta/*`, веб-поиск, получение и парсинг страниц
- Трансляция форматов идёт через OpenAI как промежуточный формат — для хрупких пар зарегистрированы прямые маршруты (блоки thinking, идентификаторы инструментов)
- **145 подключаемых провайдеров** на подписочных, платных, бесплатных, локальных и медиа-маршрутах — [полный список](../docs/PROVIDERS.md)
- Адресация моделей — `provider/model` (`kr/claude-sonnet-4.5`) — префикс называет маршрут

**🪂 Устойчивость**
- Резервирование по комбинациям моделей: задайте комбинацию, и Vela пройдёт по списку, пока кто-нибудь не ответит
- Резервирование нескольких аккаунтов на каждого провайдера, ротация по кругу
- Предохранитель на каждый пул — и предохранитель **переживает перезапуск**: открытые окна сохраняются через привязанное хранилище, дедлайны ограничены потолком, а восстановленный предохранитель взводится снова после одного отказа — по тем же законам, что и в процессе
- Пороги отказов провайдера с окнами остывания (`VELA_PROVIDER_FAILURE_*`), управление учётными данными OAuth + API-ключей с автоматическим фоновым обновлением токенов

**💰 Разум о стоимости — Завет ценообразования**
- Статическая таблица цен (вход / выход / кэшированные / рассуждение / создание кэша, $/1M токенов) с шестишаговой цепочкой разрешения — переопределения провайдера, точное совпадение, наследование бесплатной модели, отсечение вендора, glob-резервирование
- Редактор цен в панели + синхронизация с models.dev — каждый запрос получает честную оценку стоимости
- Определение бесплатного тарифа: бесплатные модели наследуют ставку своего платного собрата, чтобы экономия оставалась видимой
- Стоимость вычисляется в **момент записи** и замораживается — ни бэкфилла, ни пересчёта после правок ставок

**🐚 RTK-экономитель токенов**
- Хуки предтрансляции сжимают содержимое `tool_result` до того, как запрос покинет гавань — по замыслу fail-open, никогда не трогают трассировки `is_error`
- Инжекторы промптов, задаваемые оператором (в конец / в начало), накладываются поверх встроенных экономителей
- Необязательный сайдкар [Headroom](https://github.com/chopratejas/headroom) для более глубокого сжатия

**🗝️ Завет хранения**
- Три режима, одна переменная окружения: `VELA_DB_MODE=sqlite|mysql|mirror`
- Гавань SQLite по умолчанию; MariaDB как полноценная гавань; или **mirror** — SQLite обслуживает запросы, пока каждая запись через outbox перекачивается в близнеца MariaDB под охраной сверки расхождений
- Цепочка драйверов: `better-sqlite3` → `node:sqlite` (нулевая установка на Node ≥ 22.5) → чистый JS `sql.js`; `VELA_DB_DRIVER` закрепляет один, сбой слышен громко
- **23 миграции** (`SCHEMA_VERSION = 23`) — декларативная синхронизация `TABLES` держит обе гавани и близнеца честными — см. [docs/STORAGE.md](../docs/STORAGE.md)
- Запечатанный движок резервного копирования: артефакты AES-256-GCM, уровни хранения, **учение** восстановления, опциональное плечо S3 вне площадки

**🛡️ Безопасность**
- ACL на каждый ключ — четыре слоя: виды, провайдеры, комбинации, модели (трёхсостоянные списки разрешений)
- Бюджетные шлюзы: дневные лимиты, лимиты трат, ограничения частоты на ключ
- **Пароля по умолчанию нет.** Старый `123456` отставлен (v0.9.41). Если пароль не задан, локальная консоль пускает вас без него, но **отказывает во входах издалека**, пока вы не зададите пароль (Settings → Access). API-ключи выписываются как `vela-v1-<32 hex>-<8 hex>`; формат `sk-` отвергается повсюду
- OIDC и SAML единого входа для панели, проверка силы JWT при загрузке, реестр сессий по `jti`, CSRF-замок и клиентский IP, выведенный из **TCP-сокета** (неподделываемый) — заголовкам пересылки доверяем только от локального прокси

**🖥️ Панель управления** — `http://localhost:32060/dashboard`
- **31 комната панели** (всего 36 страниц) на **35 языках интерфейса**: провайдеры и потоки OAuth, комбинации, конечные точки + API-ключи, использование по каждому ключу, квота, экономитель токенов, консоль транслятора, настройка CLI-инструментов, флот прокси, правила резервирования, инжекторы промптов, навыки, журналы запросов и консоль настроек — начните с [карты гавани](../docs/README.md)

## 🚀 Быстрый старт

### Вариант A — Docker (рекомендуется)

```bash
docker pull ghcr.io/yumamax3/vela:1.2.5
docker run -d --name vela \
  -p 32060:32060 \
  -v "$HOME/vela-data:/app/data" \
  -e DATA_DIR=/app/data \
  -e JWT_SECRET="$(openssl rand -hex 32)" \
  -e INITIAL_PASSWORD="change-me" \
  ghcr.io/yumamax3/vela:1.2.5
```

Образ **публичный** — вход в реестр не нужен — и мультиархитектурный (`linux/amd64` + `linux/arm64`). Для полной карты — близнец MariaDB, режим mirror, движок резервного копирования, сайдкар Headroom — смотрите [DOCKER.md](../DOCKER.md), [docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md) и шаблон [`docker-compose.example.yml`](../docker-compose.example.yml).

### Вариант B — npm CLI

```bash
npm install -g vela
vela
```

Лаунчер устанавливает, запускает и управляет сервером (пакет npm сохраняет имя `vela`; само приложение — приватный `vela-app`). См. [cli/README.md](../cli/README.md).

### Вариант C — Из исходников

```bash
git clone https://github.com/YumamaX3/Vela.git && cd Vela
cp .env.example .env
npm install
npm run dev          # serves on 32060
```

Продакшн: `npm run build && npm run start` (Node 22+; Bun тоже работает — `npm run dev:bun` / `build:bun` / `start:bun`).

### Затем подключите инструмент

1. Откройте `http://localhost:32060/dashboard` — **пароля по умолчанию нет.** Локальная консоль входит без него; задайте пароль в **Settings → Access**, чтобы включить удалённый доступ.
2. **Providers** → подключите одного (Kiro AI — хорошее бесплатное начало)
3. **Endpoints** → выпишите API-ключ
4. Направьте ваш инструмент на шлюз:

```
Endpoint: http://localhost:32060/v1
API Key:  vela-v1-…  (from the dashboard)
Model:    kr/claude-sonnet-4.5      # provider prefix / model name
```

Подключение по инструментам (Claude Code, Codex, Cursor, Cline, Roo, Continue) описано в [интеграционных картах](../gitbook/content/en/) — а готовые к вставке агентские навыки живут в [skills/](../skills/README.md).
