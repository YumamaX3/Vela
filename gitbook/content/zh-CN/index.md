# 欢迎使用 Vela

**通过一个端点使用 Claude、Codex 和 Gemini —— 订阅额度用尽时，继续在低价或免费的兜底方案上编码。**

Vela 是一款小巧的网关，它位于你的编码工具与 AI 提供商之间。你把每个工具都指向同一个地址，Vela 便决定每次请求由哪个提供商应答 —— 先是你已经付费的配额，然后是低价者，最后是免费者。

如果你曾目睹一个月的 Claude Code 配额白白过期，或在重构途中被速率限制耽搁了一个小时，Vela 就是为那样的下午而生的。

---

## 用大白话说，Vela 是什么？

你的编码工具（Cursor、Cline、Continue、Claude Code、Codex，以及数十种其他工具）都讲同一种语言："OpenAI 兼容" —— 给它们一个基础 URL 和一把密钥，它们就会与在那一头应答的服务对话。

在那一头应答的是 Vela。它背后坐着你连接的各个提供商 —— 你的 Claude Code 登录、你的 Codex 登录、一把 GLM 密钥、一个免费的 Kiro 账户 —— Vela 会把每个请求路由到应当服务它的那一个。

**它解决了什么：**
- ❌ 订阅配额每月白白过期
- ❌ 速率限制让你写到一半就停下
- ❌ 多个付费 API，各自一张月度账单
- ❌ 手动在提供商之间切换工具

**你换来的是：**
- ✅ **订阅用到最后一个 token** —— Claude Code、Codex、Copilot 等，实时跟踪
- ✅ **低价备用** —— GLM-4.7 每 1M token 输入 $0.60 / 输出 $2.20，MiniMax M2.1 输入 $0.30 / 输出 $1.20
- ✅ **免费兜底** —— iFlow、Qwen 和 Kiro，零成本
- ✅ **自动回退** —— 一个用尽，下一个接手，你甚至察觉不到

## 核心特性

### 🔄 三层，一个端点

只需设置一次顺序，然后继续编码：

```
第 1 层（订阅）：Claude Code → Codex → Copilot
  ↓ 配额耗尽
第 2 层（低价）：GLM-4.7 → MiniMax M2.1 → Kimi
  ↓ 触达支出上限
第 3 层（免费）：iFlow → Qwen → Kiro

→ 下一个接手。你继续敲键盘。
```

第 2 层和第 3 层不会自动生成 —— 需要你来构建。**组合**就是为这条链命名的方式；[组合指南](features/combos.md)会带你几步点出一个。

### 📊 配额跟踪

- 每个提供商的 token 消耗，实时呈现
- 重置倒计时（每小时、每日、每周、每月）
- 付费层的成本估算
- 按 API Key 设置预算上限，如果你想要硬性限制

### 🎯 适用于任何 OpenAI 兼容工具

✅ **Cursor** • **Cline** • **Claude Code** • **Codex CLI** • **Roo** • **Continue** • **任何支持基础 URL 的工具**

### 💰 一个现实的月份

一位每月消耗 100M token 的开发者，大部分流量走的是已经拥有的配额：

```
60M 经 Gemini CLI        : $0   （免费额度，上游数字）
30M 经 Claude Code       : $0   （你已在付费的订阅）
 8M 经 GLM-4.7            : 约 $4.80
 2M 经 MiniMax M2.1       : 约 $0.40
```

[低价提供商页面](providers/cheap.md)会逐行演算这些数字。

## Vela 支持多少提供商？

诚实的答案要有三个数字，因为它们衡量的是三种不同的东西。三个数字都于 2026-10-28 在 1.2.5 版本上测得，你随时可以自行重新推导：

| 数量 | 含义 | 如何自行核对 |
|-|-|-|
| **189** | 注册表中的提供商文件 —— 任何人写过的全部 | `ls open-sse/providers/registry/*.js \| grep -v index.js \| wc -l` |
| **186** | 应用实际可见的条目（有三个文件被刻意排除在导入之外） | `node -e "import('./open-sse/providers/registry/index.js').then(m=>console.log(m.default.length))"` |
| **145** | 请求实际能够抵达的传输 | `node -e "import('./open-sse/providers/index.js').then(m=>console.log(Object.keys(m.PROVIDERS).length))"` |

也就是说：**145 个提供商你可以拨通**，在应用可见的 186 个之中，在这 189 个被写下的之中。

这些差距本身就能说明问题。三个文件（`devin-cli`、`trae`、`windsurf`）存在于磁盘上，却在生成的索引中被注释掉 —— 两个缺乏可靠的工具调用支持，一个会启动带 shell 访问权限的本地智能体 —— 因此谁也看不见它们。186 个中的另外 41 个是没有声明任何传输的条目：媒体、工具，或进行中的工作，任何发出聊天请求的东西都无法抵达。无论是导入还是未导入的文件，对阅读注册表的人都仍然有意义；它们都不是营销数字。在你自己的克隆里运行这三条命令，你得到的是当天的数字，而不是下个月的。

按认证方式划分，应用可见的这 186 个分为 131 个 API Key 提供商、23 个 OAuth 登录、22 条免费层通道、7 个 Web Cookie 提供商，以及 3 个完全无需账户的。你不需要记住这些 —— 仪表盘的 **提供商** 房间会列出它们。

## 人们为何选择 Vela

### 让已经付过的钱发挥全部价值

已经在用 Claude Code 或 Codex？Vela 会跟踪还剩多少配额、在账户之间切换，并保持到重置的倒计时。目标很简单：在你买下的东西过期之前用掉它。

### 好东西用尽时，依然便宜

| 提供商 | 每 1M token | 典型重置 |
|----------|---------------|---------------|
| **GLM-4.7** | 输入 $0.60 / 输出 $2.20 | 每日 |
| **MiniMax M2.1** | 输入 $0.30 / 输出 $1.20 | 滚动窗口 |
| **Kimi** | 订阅套餐 | 每月 |

这些是 Vela 自身用于成本估算的费率（`open-sse/providers/pricing.js`）；你提供商的账单才是最终定论。

### 当其他一切都耗尽时，仍然免费

- **iFlow** —— 免费账户，众多模型（Qwen3、Kimi K2、GLM 4.7、DeepSeek 等）
- **Qwen** —— 在 Qwen 自有账户上的 Qwen 模型
- **Kiro** —— 通过 AWS Builder ID 使用 Claude 模型

免费通道有速率限制，而且会毫无预告地变化。它们是最后一线，而非第一线。

## 快速开始

如果已安装 Node.js 20 或更高版本，只需两分钟：

```bash
# 启动器会自行安装并启动网关
npm install -g vela
vela
```

仪表盘会自动在 **http://localhost:32060/dashboard** 打开。没有默认密码：本地浏览器可直接进入，而在你于 **设置 → 访问** 中设置密码之前，远程登录始终关闭。

然后，在任何编码工具中：

```
端点：http://localhost:32060/v1
API Key： [在 仪表盘 → 端点与密钥 → 创建密钥 中创建]
模型：   cc/claude-opus-5        （或任何模型，或一个组合名称）
```

[→ 完整的入门指南](getting-started/quick-start.md)

## 人们用它做什么

### 独立开发者
让所有工具跑在同一个端点上，让订阅优先，不再为"以防万一"而额外购买 API 额度。

### 小团队
在一台小服务器上跑一个 Vela，给每个人分发一把带独立支出上限的 API Key，在一个地方查看用量。

### 在多台机器上编码
把 Vela 部署到 VPS 或容器上，从笔记本、平板或手机访问它。[云端指南](deployment/cloud.md)涵盖了这些，包括你需要的反向代理。
