# 智能路由与自动回退

Vela 不做猜测。每个请求的去向都有理由：你请求的模型、应当服务它的账户，以及 —— 如果失败 —— 排在后面的下一个。

本页逐一解释这些部件，这样当请求落在意料之外的地方时，你就能准确知道该拧哪个旋钮。

---

## 一次请求的形状

```
你的工具
   ↓  POST /v1/chat/completions，model: "premium-coding"
Vela
   ↓  "premium-coding" 是组合吗？      → 是：遍历它的链
   ↓  否则：是 prefix/model 吗？       → 解析提供商 + 模型
   ↓  该提供商用哪个账户？             → 连接顺序，或轮询
   ↓  API Key 允许吗？                 → 密钥范围
   ↓  密钥在预算内吗？                 → 不在则 429
   ↓  调用上游
   ↓  失败？                           → 链上的下一个模型（组合）
回复
```

这条路径上没有任何东西会悄悄重排你的优先级。如果你请求的是订阅模型，你得到它，或者得到一个错误 —— 除非你在使用组合，那种情况下你得到你列出的下一个模型。

---

## 组合回退

组合是唯一能让请求转到*另一个模型*的机制：

```
cc/claude-opus-5 → glm/glm-4.7 → kr/claude-sonnet-4.5
```

它在请求失败时前进 —— 配额错误、速率限制、超时、策略拒绝、未知模型 —— 而在请求只是*可能*稍后失败时原地不动。完整规则以及如何构建一个，见[组合](combos.md)。

## 账户轮换

在同一个提供商内，多个连接可以分担工作。**设置 → 路由** 提供轮询（在连接之间分摊）或填充优先（用一个直到它抱怨），并有一个粘性限制，让对话在一段时间内停留在同一账户上。这就是你无需操心就能用上两个、三个 Claude 账户的方式。

## 密钥范围与预算

每个 API Key 都可以限定到特定提供商、模型或组合，并获得 token 预算与支出上限。触达上限时，请求会被拒绝，返回携带 `budget_exceeded` 代码的 `429` —— 一次明确的停止，而非安静的降级。

## 每条通道的用途

**订阅 —— 若质量重要，优先使用**
- Claude Code、Codex、Copilot、Antigravity、Kimi
- 你已经为这些付费；目标是趁额度过期前用掉它

**低价 —— 中间地带**
- GLM-4.7（每 1M 输入 $0.60 / 输出 $2.20）、MiniMax M2.1（输入 $0.30 / 输出 $1.20）、Kimi 套餐
- 零售 API 价格的一小部分，对大多数工作足够好

**免费 —— 最后防线**
- iFlow、Qwen、Kiro
- 有限速、不稳定，但零成本

## 观察这一切发生

```
仪表盘 → 用量             请求、token 与成本的实时视图
仪表盘 → 配额             按提供商：已用、剩余、重置倒计时
仪表盘 → Routed by Combo  究竟是哪个模型在应答
仪表盘 → 日志港           当你需要细节时的请求账本
```

如果某个组合每次都落在最后一级，**配额** 会在几秒内告诉你原因。

## 重要的配置

### 路由策略

```
仪表盘 → 设置 → 路由
  轮询                  在多个连接之间分摊请求
  粘性限制              一段对话在同一连接上停留多久
  组合轮询              在组合成员之间轮换，而不是逐级下落
```

### 回退规则

除了组合，Vela 还有 **Fallback Rules** —— 由运维者定义、以出错原因为键的规则：

- 特定的 HTTP 状态码
- 被拒绝的提示词（内容策略）
- 过小的上下文窗口
- 超时
- 任何错误

规则可以串联，并可在上线前于演练面板中测试。当"在*那种情况*发生时试试另一个模型"是一项策略而非偏好时，它们就是正确的工具。在侧边栏的 **Fallback Rules** 下找到它们。

### 按密钥的上限

```
仪表盘 → 端点与密钥 → 创建密钥 / 编辑
  速率限制、token 预算、支出上限、提供商/模型范围
```

这是唯一能阻止支出的机制。对任何无人值守运行的密钥都请使用它。

## 示例

### 示例 1：订阅优先

```
模型: premium-coding
  1. cc/claude-opus-5
  2. glm/glm-4.7
  3. if/qwen3-coder-plus
```

上午：Claude 应答。下午，滚动窗口关闭时：GLM 应答。傍晚，卡被拒付时：iFlow 应答。你继续敲键盘。

### 示例 2：带支出上限

给该密钥每月 $20 的上限。通过 GLM 和 MiniMax 工作直到触达上限；从此之后每个付费请求都被 `429` 拒绝，而免费通道仍在应答。账单可预测，没有意外发票。

### 示例 3：仅订阅

单一模型，不用组合。如果窗口关闭，你得到提供商的错误。这是有意为之：有些人宁愿等，也不愿花钱。

## 良好习惯

### 1. 让困难的工作交给订阅

Opus 和 GPT-5.6 级别的模型在架构和调试上挣回它们的价格。低价模型则在另外那百分之八十上挣回它们的。

### 2. 以免费通道收尾

以付费模型收尾的链，终结于一扇关闭的门。

### 3. 关注重置时间，而不只是百分比

滚动窗口与固定窗口的行为不同。每月重置前一天的繁重工作，是被白白扔掉的额度。

### 4. 每个工具或每个人一把密钥

范围与预算都是按密钥的。共用一把密钥意味着共用一个上限，也无法分辨谁花了多少。

## 故障排查

### "No available provider" / "quota exhausted"

在 **配额** 中查看倒计时，然后检查组合是否以免费模型收尾。如果是，而免费提供商也耗尽了，那就是上游的糟糕一天，而不是本地故障。

### 它总是在回退

- 查看第一级：过期的 OAuth token 是最常见的原因。
- 查看提供商的状态页。
- 确认模型 id 仍然存在（`/v1/models`）。

### 成本高于组合所暗示的

- 阅读 **Routed by Combo**：它落到了比你设想更靠后的链上。
- 记住在每条通道上，输出 token 的价格都是输入的数倍。
- 检查链中是否有 `-highspeed` 或更大的 `glm-5.x` 模型。

### 请求被 429 拒绝

读取响应中的代码：速率限制、密钥范围，或预算。每一个都指明了它拒绝了什么，以及为什么。
