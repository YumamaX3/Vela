# 低价提供商 —— 超低价备用

订阅配额用完之后，一个好的低价模型每天只花几美元，而不是每小时几美元。本页介绍 Vela 内置的三个低价提供商、Vela 用于估算成本的确切费率，以及如何把它们放在订阅身后。

> **关于这些数字。** 本页的每一个费率都来自本版本的 `open-sse/providers/pricing.js`（Vela 1.2.5）。这正是 Vela 自身在成本估算中记账所依据的费率。你提供商的账单仍是最终定论 —— 费率由上游设定，并会在没有预告的情况下变化。

---

## 概览

低价通道位于订阅与免费提供商**之间**：

- 💰 **GLM-4.7** —— 每 1M token 输入 $0.60 / 输出 $2.20（`glm/glm-4.7`）
- 💰 **MiniMax M2.1** —— 每 1M token 输入 $0.30 / 输出 $1.20（`minimax/MiniMax-M2.1`）
- 💰 **Kimi** —— 订阅套餐，适合稳定的长上下文使用（`kimi/...`）

**思路：** 当订阅窗口关闭时，低价通道让你以零售 API 价格的一小部分继续工作 —— 并且一个免费提供商始终排在最后，以备连这也负担不起时。

---

## GLM-4.7

### 定价

| 项目 | 费率 |
|------|------|
| 输入 | 每 1M token $0.60 |
| 输出 | 每 1M token $2.20 |
| 缓存输入 | 每 1M token $0.11 |

这就是 Vela 记账的费率：输入大约是典型每 1M $20 零售 API 的十四分之一，输出约为十分之一。

**演算示例 —— 10M token，一半读一半写：**

```
输入:   5M × $0.60 = $3.00
输出:  5M × $2.20 = $11.00
总计:              $14.00
```

**演算示例 —— 一个典型的编码日，8M token，读写比 3:1：**

```
输入:   6M × $0.60 = $3.60
输出:  2M × $2.20 = $4.40
总计:              $8.00
```

### 配置

**第 1 步：获取密钥**

在你的 GLM 提供商处（视地区为 Zhipu / Z.ai）创建账户并生成 API Key。

**第 2 步：添加到 Vela**

```
仪表盘 → 提供商 → GLM → 添加 API Key → 粘贴 → 保存
```

**第 3 步：使用它**

```
模型: glm/glm-4.7
```

### 该通道上的模型

| 模型 | 适合 |
|-------|----------|
| `glm/glm-4.7` | 性价比主力：编码与通用任务 |
| `glm/glm-4.6v` | 视觉 —— 读取截图与图表 |
| `glm/glm-5`、`glm/glm-5.2`、`glm/glm-5.3` | 更新、更强，也更贵 |
| `glm/glm-5.3-flash` | 视觉，更低的价格 |

### 实用提示

- **缓存感知路由很划算。** GLM 的缓存输入费率是新鲜输入费率的五分之一；保持前缀稳定的长对话成本低得多。
- **GLM 有自己的配额窗口。** 仪表盘的 **配额** 页面显示你账户的剩余额度与重置倒计时。
- **把它放在第二，而不是第一**，除非你在刻意优化成本 —— Claude 和 Codex 在真正困难的问题上更好。

## MiniMax M2.1

### 定价

| 项目 | 费率 |
|------|------|
| 输入 | 每 1M token $0.30 |
| 输出 | 每 1M token $1.20 |
| 缓存输入 | 每 1M token $0.03 |

这是 Vela 内置的最便宜的付费通道，也是长上下文工作的宠儿。

**演算示例 —— 10M token，一半读一半写：**

```
输入:   5M × $0.30 = $1.50
输出:  5M × $1.20 = $6.00
总计:              $7.50
```

**演算示例 —— 一个典型的编码日，8M token，读写比 3:1：**

```
输入:   6M × $0.30 = $1.80
输出:  2M × $1.20 = $2.40
总计:              $4.20
```

### 配置

**第 1 步：获取密钥** —— 从 MiniMax 的平台。

**第 2 步：添加它**

```
仪表盘 → 提供商 → MiniMax → 添加 API Key → 粘贴 → 保存
```

**第 3 步：使用它**

```
模型: minimax/MiniMax-M2.1
```

### 该通道上的模型

| 模型 | 说明 |
|-------|-------|
| `minimax/MiniMax-M2.1` | 性价比之选，$0.30 / $1.20 |
| `minimax/MiniMax-M2.5`、`minimax/MiniMax-M2.7` | 更新代际，同样的标价 |
| `minimax/MiniMax-M2.5-highspeed` | 更快的档位，$0.60 / $2.40 |
| `minimax/MiniMax-M3` | 当前旗舰 |
| `minimax/minimax-image-01`、`minimax/speech-2.8-hd` | 图像与语音服务 |

### 实用提示

- **长上下文正是选择它的理由。** MiniMax 模型能接受非常庞大的输入，这让它成为订阅窗口关闭时整文件、整仓库提问的好归宿。
- **留意 `-highspeed` 变体** —— 它们的价格翻倍。对交互式工作值得，对批处理任务浪费。

## Kimi（固定套餐）

### 定价

Kimi 销售的是编码套餐，而非按 token 零售。Vela 可以通过登录或 API Key 访问它们，取决于你的账户提供哪一种。

**它为何值得一席之地：** 对于稳定、可预测的用量，固定月费胜过按 token 计费，而 Kimi 模型在长上下文方面很强。

### 配置

```
仪表盘 → 提供商 → Kimi → 连接（登录）   —— 或 ——   添加 API Key
```

```
模型: kimi/kimi-latest
       kimi/kimi-k2.5
       kimi/k3
```

## 并排对比

| 提供商 | 输入 /1M | 输出 /1M | 形态 | 最适合 |
|----------|-----------|------------|-------|----------|
| **GLM-4.7** | $0.60 | $2.20 | 按量计费，自有配额窗口 | 日常低价编码 |
| **MiniMax M2.1** | $0.30 | $1.20 | 按量计费 | 最便宜、长上下文 |
| **Kimi** | 按套餐 | 按套餐 | 订阅 | 稳定用量 |
| 供对比的零售 API | 约 $20 | 约 $20（或更高） | 按量计费 | — |

把这张表读作"订阅用完之后先试哪个"：要成本选 MiniMax，要每美元质量选 GLM，若你已有套餐则选 Kimi。

## 让这条通道发挥作用

### Cursor、Cline、Continue、Roo

```
基础 URL：http://localhost:32060/v1
API Key： [你的 Vela 密钥]
模型：    glm/glm-4.7        （或 minimax/MiniMax-M2.1，或一个组合名）
```

### 低价优先的组合

```
仪表盘 → 组合 → 创建
  名称：   cheap-backup
  模型：   1. glm/glm-4.7
          2. minimax/MiniMax-M2.1
          3. if/qwen3-coder-plus      ← 免费兜底
```

在任何需要填写模型名的地方使用 `cheap-backup`。低价第一，更低价第二，末尾免费。

### 订阅优先的组合

```
  模型：   1. cc/claude-opus-5
          2. glm/glm-4.7
          3. minimax/MiniMax-M2.1
          4. kr/claude-sonnet-4.5     ← 免费兜底
```

## 钱究竟花在哪里

### 一个现实的月份，100M token

```
60M 经免费额度            : $0     （上游额度，非 Vela 提供）
30M 经订阅                : $0     （已付费）
 8M 经 GLM-4.7             : 约 $4.80  （输入加权）
 2M 经 MiniMax M2.1        : 约 $0.40  （输入加权）
```

低价通道很少是账单本身。它是一份保险，让订阅枯竭时你还能继续编码。

### 设置上限

如果你把 API Key 交给无人值守运行的工具，请为该密钥设置支出上限：

```
仪表盘 → 端点与密钥 → 创建密钥（或编辑现有密钥）
→ 预算：每日 / 每周 / 每月 token 预算与支出上限
```

触达上限时，Vela 会以明确说明的 429 拒绝请求。它**不会**悄悄把你转到更便宜的模型 —— 支出上限按设计就是硬停止。

## 故障排查

### 低价通道上出现 "Quota exhausted"

每个提供商都有自己的窗口。在 **配额** 中查看重置倒计时，或让组合落到免费通道。

### "API key invalid"

- 重新粘贴密钥 —— 尾随空格通常是罪魁祸首。
- 检查账户确实有余额；零余额账户常常以认证形状的错误应答。
- 如果密钥曾被粘贴到公开的地方，请重新生成。

### "My bill is higher than the estimate"

- Vela 依据 `pricing.js` 中的费率进行估算；提供商可能在 Vela 更新之前更改零售费率。
- 长上下文与输出密集的工作比短提示词贵得多 —— 在这条通道上，输出价格是输入的 3–4 倍。
- `-highspeed` 与 `glm-5.x` 变体明显比标价模型更贵。

### "I want the cheapest possible"

把 MiniMax M2.1 放第一，GLM 第二，末尾放一个免费提供商 —— 并考虑是否干脆把 Antigravity（免费）放在最前。
