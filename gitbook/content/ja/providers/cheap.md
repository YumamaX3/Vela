# 格安プロバイダー - 超低価格のバックアップ

サブスクリプションのクォータが尽きたとき、良い格安モデルは一日数ドルで済ませてくれます。一時間数ドルではなく。このページでは、Velaが同梱する3つの格安プロバイダー、コスト見積もりにVela自身が使う正確な料率、そしてそれらをサブスクリプションの背後に置く方法を扱います。

> **数字について。** このページのすべての料率は、このリリース(Vela 1.2.5)の`open-sse/providers/pricing.js`から来ています。Vela自身がコスト見積もりでその額を計上する、という意味です。最終的な裁きはやはりプロバイダーの請求書です — 料率は上流が決め、予告なく変わります。

---

## 概要

格安のレーンは、サブスクリプションと無料プロバイダーの**あいだ**に座ります:

- 💰 **GLM-4.7** — 100万トークンあたり入力$0.60 / 出力$2.20(`glm/glm-4.7`)
- 💰 **MiniMax M2.1** — 100万トークンあたり入力$0.30 / 出力$1.20(`minimax/MiniMax-M2.1`)
- 💰 **Kimi** — 定常的な長コンテキストの利用向けの、サブスクリプションプラン(`kimi/...`)

**考え方:** サブスクリプションの窓が閉じたら、格安のレーンが小売APIの価格の何分の一かで、あなたを働かせ続けます — そしてそれすら重いときのために、無料プロバイダーが列の最後に残ります。

## GLM-4.7

### 料金

| 項目 | 料率 |
|------|------|
| 入力 | 100万トークンあたり$0.60 |
| 出力 | 100万トークンあたり$2.20 |
| キャッシュ入力 | 100万トークンあたり$0.11 |

これがVelaが計上する料率です: 典型的な100万あたり$20の小売APIに対して、入力ではおよそ14分の1、出力ではおよそ10分の1。

**計算例 — 1000万トークン、読みと書きが半分ずつ:**

```
Input:   5M × $0.60 = $3.00
Output:  5M × $2.20 = $11.00
Total:              $14.00
```

**計算例 — 典型的なコーディングの一日、読み書き3:1で800万トークン:**

```
Input:   6M × $0.60 = $3.60
Output:  2M × $2.20 = $4.40
Total:              $8.00
```

### セットアップ

**ステップ1: キーを手に入れる**

お使いのGLMプロバイダー(地域によってZhipu / Z.ai)でアカウントを作り、APIキーを生成します。

**ステップ2: Velaに追加する**

```
Dashboard → Providers → GLM → Add API key → paste → Save
```

**ステップ3: 使う**

```
Model: glm/glm-4.7
```

### このレーンで使えるモデル

| モデル | 向いていること |
|-------|----------|
| `glm/glm-4.7` | 価格対性能の主力: コーディングと一般的な作業 |
| `glm/glm-4.6v` | 視覚 — スクリーンショットや図を読む |
| `glm/glm-5`、`glm/glm-5.2`、`glm/glm-5.3` | より新しく、より強く、より高い |
| `glm/glm-5.3-flash` | 視覚を、より低い価格で |

### 実践的なメモ

- **キャッシュを意識したルーティングは報われます。** GLMのキャッシュ入力の料率は新鮮な入力の5分の1です。接頭辞を据え置いた長い会話は、ずっと安くつきます。
- **GLMには独自のクォータの窓があります。** ダッシュボードの**Quota**ページが、アカウントの残りの割り当てとリセットのカウントダウンを示します。
- **コストを意図的に最適化しているのでないかぎり、先頭ではなく2番目に**。本当に難しい問題ではClaudeとCodexのほうが優れています。

## MiniMax M2.1

### 料金

| 項目 | 料率 |
|------|------|
| 入力 | 100万トークンあたり$0.30 |
| 出力 | 100万トークンあたり$1.20 |
| キャッシュ入力 | 100万トークンあたり$0.03 |

Velaが同梱する有料のレーンで最も安く、長いコンテキストの作業で人気です。

**計算例 — 1000万トークン、読みと書きが半分ずつ:**

```
Input:   5M × $0.30 = $1.50
Output:  5M × $1.20 = $6.00
Total:              $7.50
```

**計算例 — 典型的なコーディングの一日、3:1で800万トークン:**

```
Input:   6M × $0.30 = $1.80
Output:  2M × $1.20 = $2.40
Total:              $4.20
```

### セットアップ

**ステップ1: キーを手に入れる** — MiniMaxのプラットフォームから。

**ステップ2: 追加する**

```
Dashboard → Providers → MiniMax → Add API key → paste → Save
```

**ステップ3: 使う**

```
Model: minimax/MiniMax-M2.1
```

### このレーンで使えるモデル

| モデル | メモ |
|-------|-------|
| `minimax/MiniMax-M2.1` | 価格対性能の選択、$0.30 / $1.20 |
| `minimax/MiniMax-M2.5`、`minimax/MiniMax-M2.7` | 新しい世代、表看板の料率は同じ |
| `minimax/MiniMax-M2.5-highspeed` | より速い階層、$0.60 / $2.40 |
| `minimax/MiniMax-M3` | 現在の旗艦 |
| `minimax/minimax-image-01`、`minimax/speech-2.8-hd` | 画像と音声のサービス |

### 実践的なメモ

- **長いコンテキストこそが、これを選ぶ理由です。** MiniMaxのモデルは非常に大きな入力を請け負えるので、サブスクリプションの窓が閉じているときの、ファイル丸ごとやリポジトリ丸ごとの問いの住みかとして良いのです。
- **`-highspeed`の変種に気をつけて** — 費用は2倍です。対話的な作業には値し、バッチの処理には贅沢です。

## Kimi(定額プラン)

### 料金

Kimiはトークン単位の小売ではなく、コーディングプランを売っています。VelaはログインかAPIキーで、あなたのアカウントが提供するほうで届けます。

**ひと座の価値がある理由:** 定常的で予測できる利用なら、定額の月額プランはトークン単位の課金に勝ります。そしてKimiのモデルは長いコンテキストに強い。

### セットアップ

```
Dashboard → Providers → Kimi → Connect (login)   — or —   Add API key
```

```
Model: kimi/kimi-latest
       kimi/kimi-k2.5
       kimi/k3
```

## 並べて見る

| プロバイダー | 入力 /100万 | 出力 /100万 | 形 | 最も向く用途 |
|----------|-----------|------------|-------|----------|
| **GLM-4.7** | $0.60 | $2.20 | 従量、独自のクォータの窓 | 日常の格安コーディング |
| **MiniMax M2.1** | $0.30 | $1.20 | 従量 | 最も安い、長いコンテキスト |
| **Kimi** | プラン制 | プラン制 | サブスクリプション | 定常的な量 |
| 比較のための小売API | 約$20 | 約$20(またはそれ以上) | 従量 | — |

この表は「サブスクリプションが終わったとき、まずどれを試すか」として読んでください: コストならMiniMax、ドルあたりの品質ならGLM、すでにプランがあるならKimi。

## このレーンを働かせる

### Cursor、Cline、Continue、Roo

```
Base URL: http://localhost:32060/v1
API Key:  [your Vela key]
Model:    glm/glm-4.7        (or minimax/MiniMax-M2.1, or a combo name)
```

### 格安優先のコンボ

```
Dashboard → Combos → Create
  Name:   cheap-backup
  Models: 1. glm/glm-4.7
          2. minimax/MiniMax-M2.1
          3. if/qwen3-coder-plus      ← free last line
```

モデル名を書くところに`cheap-backup`と書いてください。格安が先、より安いものが2番目、最後に無料。

### サブスクリプション優先のコンボ

```
  Models: 1. cc/claude-opus-5
          2. glm/glm-4.7
          3. minimax/MiniMax-M2.1
          4. kr/claude-sonnet-4.5     ← free last line
```

## お金は実際どこへ行くのか

### 現実的なひと月、1億トークン

```
60M via a free allowance    : $0     (upstream allowance, not Vela's)
30M via a subscription      : $0     (already paid)
 8M via GLM-4.7             : about $4.80  (input-weighted)
 2M via MiniMax M2.1        : about $0.40  (input-weighted)
```

格安のレーンが請求額になることは、めったにありません。サブスクリプションが乾いたときにコーディングを続けさせてくれる、保険の証書です。

### 上限を設定する

機械的に走らせるツールにAPIキーを渡すなら、そのキーに支出上限をつけてください:

```
Dashboard → Endpoint & Key → Create Key (or edit an existing one)
→ budget: daily / weekly / monthly token budget and spend cap
```

上限に達すると、Velaはそう告げる429でリクエストを断ります。黙って**安いモデルへ移すことはしません** — 支出上限は、設計として、かたい停止です。

## トラブルシューティング

### 格安のレーンで「Quota exhausted」

プロバイダーごとに独自のウィンドウがあります。**Quota**でリセットのカウントダウンを確かめるか、コンボを無料のレーンまで落とさせてください。

### 「API key invalid」

- キーをもう一度貼り直してください — 末尾の空白がいつもの犯人です。
- アカウントに実際にクレジットがあるか確かめてください。残高ゼロのアカウントは、認証系の形をしたエラーで答えることがよくあります。
- どこか公開の場所に貼った覚えがあれば、キーを作り直してください。

### 「請求額が見積もりより高い」

- Velaは`pricing.js`の料率で見積もります。プロバイダーは、Velaの表が更新される前に小売の料率を変えられます。
- 長いコンテキストと出力の多い作業は、短いプロンプトよりはるかに高くつきます — このレーンは出力が入力の3〜4倍の価格です。
- `-highspeed`や`glm-5.x`の変種は、表看板のモデルより目に見えて高いです。

### 「とにかく一番安くしたい」

MiniMax M2.1を先頭に、GLMを2番目に、無料プロバイダーを最後に — そしてAntigravity(無料)を単純に先頭にすべきかどうかも考えてみてください。
