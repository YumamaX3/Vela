# クォータ追跡と利用量の監視

Velaはすべてのものについて領収書を残します。このページはその領収書の読み方についてです: 各割り当てのどれだけが残っているか、いつリセットされるか、お金はどこへ行っているか、そしてそれにどうやってかたい上限を置くか。

---

## 概要

- **ライブの消費** — リクエストごと、モデルごと、キーごとのトークンとコスト
- **クォータと残量** — 各プロバイダーの割り当てのどれだけを使ったか
- **リセットのカウントダウン** — 窓がいつまた開くか
- **コスト見積もり** — Velaが同梱する料率から計算
- **予算の上限** — APIキーごとの、かたい停止
- **履歴** — 今日、7日、14日、30日、60日、あるいはすべての期間

---

## ダッシュボードの部屋

```
Quota     per-provider allowances and reset times
Usage     requests, tokens, cost, by period, model, combo and key
Log Harbor   the request ledger, for when you need a single request
```

### Quotaページが示すもの

接続したプロバイダーごとに、次の列を持つ行:

- **使用 / 総量** — バーとパーセントで。プロバイダーが上限を公表している場合
- **リセット** — 次の窓までのカウントダウン
- **これまでのコスト** — 従量のレーンについて

クォータのデータは、各プロバイダーから来ます。プロバイダーが使える数字を公表していないところでは、Velaはパーセントをでっち上げるのではなく、測れるもの(あなた自身の利用量)を示し、そう言います。

### Usageページが示すもの

- 選んだ期間のリクエストとトークン
- モデル、コンボ、APIキーごとに分けたコスト
- 実際に答えたモデル(**Routed by Combo**を通して)

---

## リクエストごとの追跡

すべてのリクエストは、モデル、トークン数、所要時間、結果、コストとともに記録されます。請求書に驚かされたとき、その原因となったリクエストを見つけるのはここです。

リクエストと応答の本体まで丸ごと欲しいなら、`ENABLE_REQUEST_LOGS`を有効にしてください — 大きくなり、あなたが送ったものをそのまま含むので、デフォルトでは切ってあります。

---

## クォータの形ごとの振る舞い

クォータはひとつではありません。プロバイダーはいくつかの形を使い、リセットの仕方も違います:

| 形 | 典型のプロバイダー | リセットの仕方 |
|-------|-------------------|---------------|
| **ローリングウィンドウ** | Claude Code、Codex | 窓が滑る。古い利用が抜けるにつれ割り当てが戻る |
| **固定の日次** | 一部の格安レーン | プロバイダーのタイムゾーンで、決まった時刻に |
| **月次** | Copilot、プラン | 決まった日、たいていは1日か請求日の |
| **従量クレジット** | GLM、MiniMax、たいていのAPIキー | 「リセット」はしない — 残高である |

実際の帰結: ローリングウィンドウなら一時間待てば足りることがあり、固定の日次ウィンドウなら眠ったほうがよいことがあり、残高なら払うことしか助けになりません。

---

## コストの見積もり

Velaは`open-sse/providers/pricing.js`からコストを見積もります。ここで大事なふたつの料率:

| モデル | 入力 /100万 | 出力 /100万 |
|-------|-----------|------------|
| `glm/glm-4.7` | $0.60 | $2.20 |
| `minimax/MiniMax-M2.1` | $0.30 | $1.20 |

出力は入力の3〜4倍の値段なので、出力の多い会話は、短い答えを伴う長いプロンプトよりずっと高くつきます。数字が高く見えたら、不具合を探す前に内訳を見てください。

見積もりは見積もりです: プロバイダーは、Velaの表が追いつく前に小売の料率を変えられます。権威はあなたの請求書です。

---

## 予算と上限

異なるふたつの制御があり、振る舞いも違います。どちらを有効にしたのかを知っておく価値があります。

### キーごとの予算(かたい停止)

```
Dashboard → Endpoint & Key → Create Key (or edit one)
  token budget:  daily / weekly / monthly / yearly
  spend cap:     in currency
```

キーが上限に達すると、そのキーを通したリクエストは断られます:

```
HTTP 429 — "Monthly spend cap exceeded: $20.00 of $20.00 used (budget_exceeded)"
```

それは誘導ではなく、拒否です。上限を超えないために安いモデルへ移すことはしません。止まります。「止まる」があなたの頼んだことだからです。

### ゲートウェイの予算(ゆるいしきい値とかたい上限)

利用の予算は、ゲートウェイ、キー、モデルの範囲で、日・週・月の窓をつけて設定できます。これは50%、80%、100%でアラートを出し、かたい上限を越えたら、その範囲を名指すコードとともに、はっきり拒否します。

### フォールバックとの違い

コンボは、リクエストが**失敗**したときに次のモデルへ移ります。予算は、あなたが**十分に使った**ときに断ります。どちらも偶発的に起こるものではなく、どちらもあなたのかわりに推測するものではありません。

## APIから自分の利用量を読む

ダッシュボードは、あなたも叩けるのと同じエンドポイントから読んでいます:

```bash
# Usage summary
curl "http://localhost:32060/api/usage/stats?period=7d" \
  -H "Authorization: Bearer <key>"

# Request metrics over time (for charts)
curl "http://localhost:32060/api/usage/metrics/timeseries?period=7d" \
  -H "Authorization: Bearer <key>"

# Budget definitions
curl "http://localhost:32060/api/usage/budgets" \
  -H "Authorization: Bearer <key>"
```

有効な期間: `today`、`24h`、`7d`、`14d`、`30d`、`60d`、`all`。ダッシュボードの期間の選択が使うのと同じ窓なので、毎週のスクリプトには便利です。

## アラート

アラートの記録は、予算がしきい値を越えたときに作られ、設定に応じて、ダッシュボードのバナー、DiscordのWebhook、n8nのWebhookへ届けられます。

月次のサマリのメールは、Velaがひとりでに送るものではありません。欲しければ、上のAPIとcronジョブで、10行のスクリプトになります。

## 良い習慣

### 1. 一日に一度、目をやる

**Quota**ページは10秒で済みます。どんな生産性ツールより、あなたの一週間について多くを教えてくれます。

### 2. 見守りのいらないキーには上限を

エージェント、バックグラウンドのジョブ、ループするもの、すべてに。一度決めた上限は、一度読む請求書に勝ります。

### 3. ツールごとに自分のキーを

そうすれば、キーごとの利用レポートに実際の意味が生まれます。

### 4. 退屈な仕事には安いモデルを

「コミットメッセージを書いて」をGLMの先頭に置くコンボは、Opusに送るコンボよりずっと安く、同じくらい良く答えます。

### 5. 見積もりは見積もりとして扱う

それらは公表された料率とトークン数から導かれています。予算を組むには十分に正確で、請求書と議論するには足りません。

## トラブルシューティング

### クォータは使われていると出るのに、リクエストが失敗する

プロバイダーが、Velaに見えない制限をかけているのかもしれません(アカウント単位の上限、毎分のレート制限)。クォータの数字は導きであって、約束ではありません。別のモデルを試すか、プロバイダーのステータスページを確かめてください。

### コストがおかしい

1. 料率を確かめてください: **格安プロバイダー**にVelaが同梱するものが並んでいます。
2. 内訳を確かめてください — 出力トークンが大半を占めます。
3. モデルを確かめてください — `-highspeed`や大きめの変種は高くつきます。
4. プロバイダーが価格を変えたなら、表が更新されるまで見積もりはずれます。

### リセットのカウントダウンが止まって見える

ページを再読み込みしてください。クォータのデータは表示時に取得されます。リセット時刻を公表しているプロバイダーでカウントダウンそのものが違うなら、それはVelaが計算しているのではなく表示している上流の詳細です。

### 予算に達したが、続けたい

**Endpoint & Key**でキーの予算を編集するか、別のキーを使ってください。拒否は、上限が仕事をしているという意味です。
