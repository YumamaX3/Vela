# Clineとの連携

ClineはVS Codeの拡張機能で、あなたのかわりにコードを読み、編集し、実行します。Velaに向ければ、接続したモデルなら何でも手に入ります — さらに、仕事の途中でクォータが閉じたときのフォールバックの鎖も。

## 前提条件

- VS Codeがインストール済み
- Clineの拡張機能を、VS Codeのマーケットプレイスからインストール済み
- Velaがローカルで動いているか、届くクラウドのエンドポイントがある
- Velaのダッシュボード(**Endpoint & Key → Create Key**)で作ったAPIキー

## セットアップ

### 1. Clineの設定を開く

VS CodeのサイドバーでClineのアイコンをクリックし、Clineのパネルの歯車のアイコンをクリックします。

### 2. OpenAI Compatibleのプロバイダーを選ぶ

**API Provider**のドロップダウンで、**OpenAI Compatible**を選びます。これがVelaにとって正しい選択です — OpenAIの形のベースURLとキーを受け入れます。

### 3. ベースURLを設定する

```
http://localhost:32060/v1
```

`/v1`を含めてください。クラウドへのデプロイは、ホストが違うだけで同じ形です:

```
https://your-domain.example/v1
```

### 4. キーを貼り付ける

Velaのキーは`vela-v1-<id>-<checksum>`の形をしています。作成時に一度だけ表示されるので、なくしたなら**Endpoint & Key**で新しく作ってください。

### 5. モデルIDを設定する

Clineは自由入力のモデルIDを受け取ります。Velaが解決するものを使ってください:

```
cc/claude-opus-5
cc/claude-sonnet-5
glm/glm-4.7
premium-coding            ← a combo name works too
```

### 6. 保存する

設定パネルを閉じてください。Clineは打つそばから保存します。小さなメッセージを送って確かめ、Velaダッシュボードの**Usage**を確かめてください。

## 設定例

```
API Provider:  OpenAI Compatible
Base URL:      http://localhost:32060/v1
API Key:       vela-v1-xxxxxxxx-xxxxxxxx
Model:         cc/claude-opus-5
```

### ダッシュボードが書き出すもの

Clineは設定をディスク上のふたつのファイルに保ちます。ダッシュボードのQuick Connectはまさにこの形を出力し、クリックよりファイルの編集が好きなら、手で貼り付けることもできます:

```json
// ~/.cline/data/globalState.json
{ "openAiBaseUrl": "http://localhost:32060", "actModeApiProvider": "openai" }
```

```json
// ~/.cline/data/secrets.json
{ "openAiApiKey": "vela-v1-<id>-<checksum>" }
```

上のフィールドとの違いに注意してください: **ここの`openAiBaseUrl`は`/v1`を省いています** — パスはCline自身が足します。そのフィールドに`http://localhost:32060/v1`というベースURLを入れると、`/v1/v1/chat/completions`になり、404になります。ダッシュボードのスニペットを使うか、接尾辞を扱ってくれるCline自身の設定パネルからURLを入力してください。

## 利用できるモデル

ゲートウェイが一覧するものなら何でも: `curl http://localhost:32060/v1/models -H "Authorization: Bearer <key>"`。

| モデル | レーン | 向いていること |
|-------|------|----------|
| `cc/claude-opus-5` | Claudeサブスクリプション | 複数ファイルにまたがる複雑な作業 |
| `cc/claude-sonnet-5` | Claudeサブスクリプション | 日常の編集 |
| `cx/gpt-5.6-sol` | Codexサブスクリプション | 難しいコーディングの問題 |
| `glm/glm-4.7` | 格安 | 予算を抑えた長時間の実行 |
| `minimax/MiniMax-M2.1` | 最も安い | 大きなコンテキスト |
| `kr/claude-sonnet-4.5` | 無料 | 有料のレーンが乾いたとき |

> **`cc/`のレーンについて。** Claude Codeのプロバイダー(`claude`、別名`cc`)は、このリリースが同梱するレジストリで**非推奨**、**リスクの注意書きつき**と記されています。動きますし、多くの人がAnthropicのサブスクリプションに欲しいものです — しかし、予告なく変わりうる文書化されていないClaude Codeのインターフェースに依存しています。失敗し始めたら、無料の`kr/`のClaudeモデルと`cx/`のレーンが、安定した代替です。

## 使い方

### チャット

Clineのパネルで打ってEnterを押します。Clineは会話と、読むことを選んだファイルを、Velaを通して送ります。

### コード生成

変更を頼みます(「このエンドポイントにページングを足して」)。Clineが編集を提案し、受け入れる前にあなたが目を通します — どんなエージェントに対しても払うのと同じ注意を。

### ファイル操作

Clineはファイルを作り、変え、消せます。Velaはその振る舞いを変えません。どのモデルが計画し実行するかを決めるだけです。ここでのフォールバックは本当に役に立ちます: 手順のあいだのモデルの切り替えが、長い作業を動かし続けます。

## トラブルシューティング

### 「Connection failed」

1. `curl http://localhost:32060/api/health` → 答えるはず。
2. ベースURLが`/v1`で終わるか確かめてください。
3. ポート32060のファイアウォールを確かめてください。
4. VS Codeのウィンドウを再読み込みしてください(`Cmd/Ctrl + Shift + P` → 「Reload Window」)。

### 「Invalid API key」

- キーは`vela-v1-`で始まらなければなりません。古い`sk-...`形式のキーは拒否されます。
- 末尾に改行を付けずに、丸ごとコピーしてください。
- 古いキーを公開のどこかに貼った覚えがあれば、新しいものを作ってください — 古いキーはもう表示できません。

### 「Model not found」

- `/v1/models`の正確なIDを使ってください。
- そのプロバイダーが**Providers**で接続済みか確かめてください。
- モデルIDは上流で変わります。退役したIDは、どう綴っても解決されません。

### Clineが仕事の途中で止まる

たいていはクォータの窓が閉じたか、レート制限です。コンボ(`cc/claude-opus-5 → glm/glm-4.7 → kr/claude-sonnet-4.5`)があれば、止まるかわりに、次の手順が次のモデルで走れます。

## 高度な設定

### コンボを使う

```
Model: never-stuck
```

無料のプロバイダーで終わる鎖とともに。長いエージェントの実行が最も恩恵を受けます — まさに、30分ほどでクォータの壁に当たる種類の仕事だからです。

### 仕事ごとにモデルを切り替える

2、3のIDを手元に置き、仕事が変わればフィールドを変えます:

- 重い推論とリファクタリング → `cc/claude-opus-5`
- 日常の編集 → `glm/glm-4.7`
- 試験 → `kr/claude-sonnet-4.5`

### タイムアウト

長いコンテキストの大きな編集は、Clineのリクエストのタイムアウトを越えることがあります。Clineにその選択肢があればVS Codeの設定で上げるか、作業を分けてください — Velaはプロバイダーが流す速さで流します。

## ベストプラクティス

1. **Clineに自分のキーを**、支出上限とともに。ループするエージェントは驚くほど速く予算を焼けます。上限があれば、それが請求書ではなく停止になります。
2. **会話を集中させておく** — コンテキストがコストの大半です。
3. **キーをコミットしない。** それはVS Codeの設定に住み、リポジトリには住みません。
4. **鎖を使うときは、どのモデルが答えたかを** **Routed by Combo**で見てください: フォールバックが働いているかがわかります。
